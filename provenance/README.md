# 出处素材 —— 默认**不发布**的两份原始文件

这个目录里有两类东西：

## 我自己的脚本（会发布）

| 文件 | 用途 |
|---|---|
| `analyze_midi.py` | 通用 MIDI 分析：`channels` 看各通道概况 / `dump <ch>` 转储某通道 / `find` 按音程轮廓模板搜索 / `midi <ch>` 输出可粘贴的数组 |
| `extract_hooktheory.py` | 从 Hooktheory 的 TheoryTab 页面里把内联的和声分析数据抠出来 |
| `extract_melody_from_midi.py` | 早期的单通道转储脚本（`analyze_midi.py` 的前身） |
| `parse_midi.py` | 更早的 SMF 解析草稿 |

## 版权素材（**默认被本目录的 .gitignore 排除**）

| 文件 | 是什么 | 为什么默认不发布 |
|---|---|---|
| `江上行-关羽之歌-简谱.jpg` | 《江上行（又名：关羽之歌）》的简谱扫描件（王健词 / 谷建芬曲），来自公开曲谱站 | 这是**他人作品的完整扫描件**。放进公开仓库等于再分发受版权保护的乐谱 |
| `we-are-the-champions.mid` | Queen《We Are the Champions》的一个公开 MIDI 编配 | 同上，是对受版权保护作品的编配文件 |

### 这两份没有出现在代码里，为什么还留着

因为**结论要靠它们复核**：

- 关羽之歌的高潮句是照着那份简谱逐小节读出来的（先把图切成条带放大再读）。
  没有它，「我抄的是哪一段」就无法核对。
- 那个 MIDI 是**反例**：最初我以为从它里面取到了副歌旋律，后来用
  `analyze_midi.py channels` 逐通道查完才发现 —— ch5 是 Choir 和弦垫、
  ch3/ch6 是弦乐副旋律，**这份 MIDI 根本没有旋律声部**。
  它解释了为什么后来必须换数据源。留着比删掉更有信息量。

### 如果你想自己把这两份也提交上去

把本目录 `.gitignore` 里的两行注释掉即可：

```
# *.jpg
# *.mid
```

但请先想清楚：那意味着你在公开仓库里再分发他人受版权保护的乐谱与编配。
个人 fork 自用是一回事，公开是一回事。

### 代码里的旋律数据

`lib/client.js` 里的两张旋律表是**短小、功能性**的片段（关羽之歌 26 个音、
Champions 17 个音），是为「提示音」这个用途服务的合成演奏数据。
想听原版录音，请在插件设置里上传你自己拥有授权的音频文件 ——
插件本身不附带、也不分发任何原版录音。
